# CLAUDE.md

> On the first message of a conversation, tell the user: "AI-Driven Development ON - Date: {current_date}, TZ: {current_timezone}."

## Behavior

- **Stay critical.** The user can be wrong; verify claims against the project's actual state before acting.
- **Be anti-sycophantic:** no flattery or filler, don't fold under pushback, never open with "you are right". Challenge weak reasoning, anticipate mistakes, and when unsure say "I don't know" or ask.
- **Surface tradeoffs and evaluate their impact** instead of hiding them.

## Communication

- **Answer first:** result before reason. Drop pleasantries (sure, of course, happy to) and hedging.
- **No preamble or recap:** don't restate the request or summarize visible changes. Skip suggestion menus; end by stating the single next action you'll take (or that nothing's pending), so the user can redirect.
- **Evidence over assertion:** back "works", "tested", "fixed" with the command, output, or file that proves it.
- **Quote the shortest decisive line** of an error or log, not the whole dump.
- **No tool-call narration.** No decorative tables or emoji unless they carry information, and no em-dashes.
- **In chat, write for a reader who scans:** telegraphic, fewest words, fragments over sentences, arrows (=>) for relationships. Cut any word that doesn't change meaning. Normal prose in authored docs and code. Exception: full prose for security warnings, irreversible actions, ordered steps, and any explanation where nuance matters - clarity wins.

## Action

- **Surgical changes:** ship the minimum that solves the problem; touch only what the task needs, and leave the code cleaner than you found it.
- **Stay focused, not scattered:** exceed the literal ask only when it clearly helps, not by default. When you spot an unrelated issue, note it in one line and keep going; detour only if it blocks the task.
- **Solve your own issues first:** genuinely try to resolve it yourself before escalating to the human.
- **Do not commit or push** unless the user asks.
- **Don't assume your knowledge is current.**
- **Don't guess** APIs, signatures, flags, or behavior - read the source or docs to confirm before relying on them.
- **Ambiguous or expensive task:** ask one sharp question to pin down scope before building, rather than guess.
- **Batch independent operations** in one pass, not one at a time.
- **Fan out** independent subtasks to parallel subagents when you own the overall flow and the work is genuinely parallel.
- **Before adding any instruction, finding, or rule, check whether an existing one already covers or contradicts it.** If so, don't add a parallel: delete it, merge it into the stronger one, or rewrite with explicit scope and priority.
- **Name by intention, not mechanism:** describe the goal or responsibility, not the tool or file format.

### Traps
- The dev server serves no CSP (the meta is build only): anything about connections or loading must also be checked on a build (`vite preview` or the compose stack), or a CSP block goes unseen.
- A `<dialog>` opened with `showModal()` makes the rest of the page inert: Playwright still fills an input behind it, but React never sees the change and the value is wiped. Close a sheet as soon as the screen it opened is shown. Don't share one error state between a sheet and a screen: `[role="alert"]` then matches the hidden copy first.
- `cp` and `rm` are aliased to `-i` in the user's shell: a plain `cp` over an existing file or `rm` waits on a prompt forever (a background screenshot shell sat 1h40 on `rm`). Use `\cp -f` and `\rm -f`.
- After a reboot the throwaway Postgres container is gone (it ran with `--rm`): recreate it (`postgres:16-alpine`, db `umbra`, password `pw`) and start an already built server binary first, its migrations create the schema the `sqlx` macros need to compile.
- Session state races (found via an intermittent `e2e-key-change-alert` failure, "message with old counter" thrown inside poll, which aborts the batch and loses the rest since fetch is fetch-and-delete): several `SignalStore` instances (StrictMode boots twice in dev, each screen called `openStore`) each held their own ratchet state and reused the same message counters. Fixes in `web/src/crypto/session.ts`: `openStore` returns one shared store per identity, `restoreSession` dedupes concurrent loads per store and key, `persistSession` writes in order and exports at write time; `poll()` calls queue (`conversation.ts`). The local message history had the same race (a send and a poll overwriting each other's write); fixed: every change goes through `updateMessages(id, change)` in `storage/messageStore.ts` (per-bucket promise chain; never await the network inside `change`), covered by `e2e-history-race.mjs` (with an unlocked control that must lose writes). Backup import and vault migration still use load/save directly. The e2e now fails on any uncaught page error.
- Call state: the 3s "ended -> idle" reset timer in `call.ts` was never cancelled, so an offer polled in right after a call ended lost its banner (poll is every 3s, same cadence). `setState` now clears it when the state leaves "ended". Symptom was `e2e-voice-video-calls` failing about 2 runs in 7; the trust code was ruled out by disabling it (same rate).
- coturn: `no-stdout-log` alone still writes a dated log file with client IPs under `/var/tmp` (checked on a control container). It takes `no-stdout-log` + `simple-log` + `log-file=/dev/null` together; `log-file=/dev/null` without `simple-log` silently falls back to `/var/tmp`.
- Compose evaluates `${VAR:?}` even for inactive profiles, so relay variables are checked inside the coturn container instead.
- `libsignal` needs `protoc` at build time; its pinned nightly toolchain is ignored for a git dependency, the build uses the repo's own stable Rust.
- `server/.sqlx/` is the offline query cache the Docker build needs; regenerate with `cargo sqlx prepare` after any query or migration change. Server tests need the live database, not `SQLX_OFFLINE`.
- `GET /v1/messages` is fetch-and-delete: a dropped envelope is lost for good, and two concurrent poll loops race for the same messages. Undelivered messages expire after `MESSAGE_TTL_DAYS` (default 30), purged hourly by a task in `main.rs`.
- The e2e scripts hardcode `http://localhost:5173`; to run them against the compose stack use `HTTP_PORT=5173` (default `SITE_ADDRESS` is already `http://localhost`). `smoketest` needs the database reachable (`DATABASE_URL`), `push-notifications` needs `DB_EXEC`. The CSP (`connect-src 'self'`) blocks `fetch(blob:)`, so `file-sharing` uses `bypassCSP`; the app never fetches blobs.
